Add `Intervals(lo, hi)`, an `.oindex` selector for runs of consecutive indices. It selects what `np.r_[lo[0]:hi[0], ...]` does and stores the intervals, not every index, so a selection stays small, also when pickled, and chunk planning costs per interval rather than per index. `GridPartition.sets` can now hold the new `IntervalSet` table, so code that dispatches on `StridedSet` and `IndexedSet`, or narrows `sets` exhaustively, needs a branch for it.
